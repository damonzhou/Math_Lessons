# 课程设计要求

每一讲必须是一节可以独立自学的完整课程，而不是知识点摘要。

必须同时包含：

1. **真实或有意义的情境**：说明这个概念为什么出现、解决什么问题；
2. **概念建立过程**：从已有知识、矛盾、观察或实验中自然推出定义；
3. **定义与边界**：包括反例、特殊情况和容易误解的地方；
4. **例题链**：从直接应用到逆向、变式、综合，题目之间有递进关系；
5. **扩展理解**：解释概念与后续数学之间的连接；
6. **数学思想**：明确指出分类、转化、整体、数形结合、构造、方程等方法；
7. **四轨拓展**：Core / Advanced / Olympiad / Informatics；
8. **当堂训练与课后作业**：不是简单重复例题；
9. **答案、提示与错因记录**；
10. **复习与下一讲连接**。

课程不能只写“定义—公式—例题—练习”，也不能只靠堆难题体现深度。

# 四轨难度体系

## Core｜课内主线

必须覆盖教材要求：

- 定义；
- 性质；
- 基本技能；
- 规范表达；
- 教材典型题型。

目标：课内知识无漏洞。

## Advanced｜校内拔高

重点包括：

- 易错辨析；
- 逆向问题；
- 条件变化；
- 参数萌芽；
- 综合题；
- 一题多解；
- 数学思想提炼。

目标：稳定解决校内中高档题和大部分压轴问题。

## Olympiad｜奥数 / 竞赛思维

只选择与当前主线自然相连的内容，例如：

- 整数性质；
- 奇偶与整除；
- 构造；
- 分类计数；
- 不变量；
- 极端思想；
- 代数技巧；
- 几何推理；
- 规律与递推。

目标：建立竞赛思维，而不是机械提前学习高年级公式。

## Informatics｜信息学数学连接

结合当前数学主题自然引出：

- 整数与数据类型；
- signed / unsigned；
- 坐标；
- 差分与 offset；
- 模运算；
- gcd / lcm；
- 进制；
- 递推；
- 组合计数；
- 图论；
- 算法复杂度中的数学。

信息学内容应解释“数学概念如何进入程序和算法”，不能只附一段无关代码。

# 第0部分：本讲怎么学

说明：

- 学习顺序；
- 哪些内容必须掌握；
- 哪些属于第一次只需理解的拓展；
- 推荐时间分配；
- 是否建议分两次完成。

---

# 第一部分：情境 / 问题导入

至少给出 1～3 个具体实例。

要求实例承担教学作用，例如：

- 暴露旧知识的不足；
- 让学生发现共同结构；
- 产生需要定义新概念的动机。

避免为了“有故事”而加入与数学无关的装饰性情节。

加入至少一个：

## 停下来想一想

让学生先预测、比较、解释或提出猜想，再继续阅读。

---

# 第二部分：概念的来源

解释：

- 为什么需要这个概念；
- 它解决了什么问题；
- 与已有知识是什么关系；
- 如果没有这个概念，会在哪里遇到困难。

必要时加入数学史小窗，但必须服务于概念理解。

---

# 第三部分：核心定义与性质

包含：

1. 正式定义；
2. 通俗解释；
3. 数学表达；
4. 特殊情况；
5. 边界条件；
6. 反例；
7. 与相近概念的区别。

核心结论建议用公式或明确的结论框突出。

---

# 第四部分：概念扩展理解

必须回答类似问题：

- 这个定义还能怎样理解？
- 换一种表示方式是否仍是同一个结构？
- 它与以后哪些知识相连？
- 有没有更一般的观点？

允许引入适度超前术语，但应标记为 Advanced / Extension，并说明当前是否需要记忆。

---

# 第五部分：例题链

例题必须递进，而不是同类型换数字。

推荐结构：

### 例题 1：直接应用

检查定义和基本操作。

### 例题 2：逆向问题

从结果反推条件。

### 例题 3：条件变化

改变参照、位置、参数或题目条件。

### 例题 4：综合应用

连接两个以上知识点。

### 例题 5：方法题

重点不在计算，而在发现方法。

每道重要例题至少包含：

- 思考入口；
- 解答过程；
- 为什么这样做；
- 方法提炼；
- 易错点或变式方向。

---

# 第六部分：错误实验室

不能只列“注意事项”。

应设计具体错误观点，例如：

> 学生甲认为……

然后分析：

1. 错在哪里；
2. 为什么容易这样错；
3. 用反例怎样推翻；
4. 正确判断流程是什么。

---

# 第七部分：数学思想 / 方法

明确本讲真正值得迁移的方法，例如：

- 分类讨论；
- 数形结合；
- 转化思想；
- 整体思想；
- 方程思想；
- 从特殊到一般；
- 基准法；
- 构造；
- 不变量。

不要只写方法名称，要用本讲例题说明它是怎样工作的。

---

# 第八部分：Advanced 扩展

设计 1～3 个与当前概念自然相关的提高主题。

要求：

- 不机械超前；
- 能解释更一般的结构；
- 为后续课程埋伏笔。

---

# 第九部分：Olympiad 连接

设计 1～3 个奥数/竞赛方向的连接点。

可以包括：

- 一道经典模型；
- 一种竞赛方法；
- 一个“为什么这样想”的思维过程。

难度不等于价值。优先选择能建立方法的题。

---

# 第十部分：Informatics 连接

说明当前数学概念在程序、算法或计算机系统中的对应物。

推荐结构：

1. 数学模型；
2. 一个最小程序实例；
3. 数学符号与程序变量的对应；
4. 后续信息学会在哪里继续使用。

---

# 第十一部分：当堂训练

至少分为：

## A. Core 基础

检查定义和基本技能。

## B. Advanced 提高

检查逆向、综合和方法迁移。

## C. Olympiad 思维

少量高价值问题。

## D. Informatics 连接

数学到程序 / 算法的迁移问题。

题量根据内容调整，不追求机械重复。

---

# 第十二部分：当堂训练答案

建议使用 `<details>` 折叠，避免学生无意中提前看到答案。

重要题给出完整思路；简单题可给结论。

---

# 第十三部分：课后作业

课后作业与课堂训练不能完全重复。

建议包含：

- A 组：基础巩固；
- B 组：理解与应用；
- C 组：Olympiad；
- D 组：Informatics。

至少包含 1 道需要解释“为什么”的题。

---

# 第十四部分：答案与提示

答案除了结果，还应对关键题写出：

- 突破口；
- 关键关系；
- 常见错误；
- 是否存在第二种方法。

---

# 第十五部分：错因记录

统一采用错因标签，例如：

- [ ] C1 概念错误
- [ ] C2 条件遗漏
- [ ] C3 符号错误
- [ ] C4 运算错误
- [ ] C5 建模困难
- [ ] C6 未分类讨论
- [ ] C7 方法选择不当
- [ ] C8 表达不规范

每讲可以增加本讲特有错因。

---

# 第十六部分：掌握度检测

设计 5～10 个不用计算器、不看讲义的口头问题。

学生应能：

- 说定义；
- 解释原因；
- 举例和反例；
- 说出方法；
- 说明与后续知识的连接。

推荐四级：

1. 会认；
2. 会用；
3. 会解释；
4. 会迁移。

---

# 第十七部分：复习计划

至少给出：

- 24 小时复习任务；
- 7 天后复习任务。

复习应以主动回忆和变式重做为主，不建议重新通读全文。

---

# 第十八部分：知识地图

用简洁文字图、关系图或公式链总结：

- 概念之间的关系；
- 方法之间的关系；
- 当前知识在整个初中数学体系中的位置。

说明：

1. 下一讲为什么自然接在这里；
2. 本讲哪个概念会继续使用；
3. 后续七、八、九年级会在哪里再次出现；
