# 课程标准 v2.0｜能力上限提升体系

> **状态**：ACTIVE 增量标准  
> **生效日期**：2026-09-02  
> **基于**：v1.3～v1.9

---

# 1. 为什么升级到 v2.0

v1.9 已经解决一个重要问题：

> 课程不能只判断“学生学会没有”，还要用 Ceiling Diagnostic 测出学生在尚未得到高阶方法提示时，能够独立走多远。

但仅仅“测上限”仍然不够。

课程最终目标不是长期记录一个固定的能力上限，而是：

> **通过课程设计本身，持续提高学生能够独立发现、迁移、建模、一般化和解决陌生问题的能力上限。**

因此 v2.0 把课程从：

```text
教知识 + 测上限
```

升级为：

```text
完整学习当前知识
→ 测当前上限
→ 有针对性地训练突破能力
→ 再测迁移
→ 延迟复测
→ 形成更高的新上限
```

这属于课程理念和训练体系的实质变化，因此升级主版本为 **v2.0**。

---

# 2. 核心原则

## 2.1 课标决定边界，不决定上限

教育部课标和当前人教版决定：

- 当前阶段必须学习什么；
- 概念边界在哪里；
- 正式 Mainline 顺序怎样安排。

但课程深度不能停在最低达标水平。

在不依赖后续知识的前提下，应把当前知识能达到的思维深度推到尽可能高。

## 2.2 能力上限不是固定属性

Ceiling Diagnostic 的结果只表示：

> **学生在当前时点、当前知识和当前提示条件下的独立表现。**

不能把某次 C5-C / C5-D 当成固定能力标签。

课程必须针对卡点安排训练，使学生以后面对不同表面结构时能够更早、更独立地发现关键关系。

## 2.3 提升上限不能靠提前灌输后续知识

不允许用：

- 高年级定理；
- 尚未学习的公式；
- 直接给出竞赛套路；
- 大量同模板机械训练；

制造“水平提高”的假象。

真正的能力提升来自：

- 更准确地读条件；
- 更主动地寻找结构；
- 能尝试不同表示；
- 能构造反例；
- 能逆向思考；
- 能从具体走向一般；
- 能解释方法为什么有效；
- 能在新表面下识别同一结构。

---

# 3. 每讲改为六层体系

v1.9 的五层体系升级为六层：

| 层级 | 名称 | 目标 |
|---|---|---|
| L1 | 教材完整层 | 当前教材节点完整无遗漏 |
| L2 | 概念深度层 | 定义、边界、反例、多表示、为什么 |
| L3 | 校内高阶层 | 逆向、参数、条件变化、综合、压轴结构 |
| L4 | 竞赛/信息学迁移层 | 权威陌生结构、算法化、跨情境迁移 |
| L5 | Ceiling Diagnostic | 测当前独立发现上限 |
| **L6** | **Ceiling Builder** | **针对 L5 暴露的卡点，系统训练并提高能力上限** |

一个 Lesson 只有 L1～L6 都有明确设计，才可以标记为：

> **最高深度 + 上限提升体系完成。**

---

# 4. Ceiling Builder｜能力上限提升模块

每讲至少设计一组 Ceiling Builder，不要求全部很长，但必须真正训练“发现能力”，而不是重复计算。

## 4.1 推荐训练类型

### A. 表示转换

同一问题尝试：

- 数字；
- 数轴/图形；
- 表格；
- 语言关系；
- 程序变量；

问：换一种表示后，隐藏关系是否变得明显？

### B. 条件变化

改变一个条件：

- 结论还成立吗？
- 哪个条件是必要的？
- 哪个条件可以删除？
- 能否构造反例？

### C. 逆向与构造

不是只问“算出答案”，还可以问：

- 已知结果，原条件可能是什么？
- 请构造一个满足条件的例子；
- 请构造一个最小反例；
- 请设计一道同结构但表面不同的题。

### D. 多方法比较

如果存在自然的两种方法：

1. 学生先任选一种；
2. 再比较两种方法的共同结构；
3. 说明什么情况下哪种方法更好。

目的不是炫技，而是提高方法选择能力。

### E. 特殊到一般

从具体数字逐步提问：

```text
这个结论只对本题成立吗？
如果把数字换成变量会怎样？
最一般需要什么条件？
```

训练“例题 → 方法 → 一般结构”。

### F. 陌生表面迁移

把已学结构换到不同情境：

- 测量；
- 坐标；
- 数据；
- 工程；
- 程序；
- 竞赛题；

要求学生先判断“这题和以前哪一种结构相同”，再决定方法。

# 5. 推荐教学顺序

一个完整 Lesson 的高阶部分推荐按：

```text
Core 完整学习
    ↓
Ceiling Diagnostic（冷启动）
    ↓
记录首个卡点
    ↓
Ceiling Builder 1：针对卡点的引导发现
    ↓
方法提炼 / 多表示 / 反例
    ↓
Ceiling Builder 2：条件变化或一般化
    ↓
Advanced / Olympiad / Informatics
    ↓
Mastery Challenge
    ↓
7天后陌生表面迁移
```

Ceiling Builder 应当位于“诊断之后、最终综合挑战之前”，使课程能够明确回答：

> **这次教学具体训练了哪一种高阶能力？**

---

# 6. Ceiling Builder 必须针对真实卡点

不能每讲机械复制同一套“拔高题”。

根据 Ceiling Diagnostic 和既有 H1～H10 习惯，选择本讲重点。

例如：

- H1 条件读取弱 → 训练删除/添加条件、必要条件判断；
- H3 容易补隐藏条件 → 训练反例构造和条件充分性；
- H5 分类筛选弱 → 训练分支和排除；
- H7 局部/整体混淆 → 训练多表示和整体关系；
- H8 估算后不验证 → 训练界限、回代和唯一性；
- H9 过早套模板 → 训练同题多表面和方法选择；
- H10 不检查结论 → 训练边界值、反例和逆向验证。

Ceiling Builder 的目标不是增加题量，而是改变解决陌生问题时的行为模式。

---

# 7. 能力提升如何验证

每讲至少区分三次表现：

## T0｜冷启动上限

Ceiling Diagnostic 第一次无 Hint 表现。

## T1｜教学后迁移

Mastery Challenge 或新的非同构问题。

## T2｜延迟迁移

约7天后用不同表面结构复测。

建议记录：

| 指标 | T0 | T1 | T2 |
|---|---|---|---|
| 是否独立识别关键结构 |  |  |  |
| 需要 Hint 等级 |  |  |  |
| 首个卡点 |  |  |  |
| 是否能解释方法 |  |  |  |
| 是否能一般化 |  |  |  |
| 是否出现同类 H 错误 |  |  |  |

真正的“上限提高”至少应表现为其中一项：

- 更少提示；
- 更快识别结构；
- 能处理更陌生的表面；
- 能主动构造反例；
- 能提出一般化；
- 能选择更合适的方法；
- 同类习惯错误减少。

---

# 8. Challenge 的三种角色正式分离

从 v2.0 起，高难题至少区分：

## Ceiling Diagnostic

测“还没教方法时能走多远”。

## Ceiling Builder

训练“怎样比原来走得更远”。

## Mastery / Final Challenge

测“经过教学和训练后，能否在新问题中稳定迁移”。

三者可以来源于同一数学主题，但不能用高度同构的同一道结构同时冒充三种功能。

---

# 9. 题源要求

AMC、CEMC、UKMT、IMO、CMO、中国数学会正式赛事、国内正式考试、CSP-J/NOI 等继续作为权威来源池。

provenance 除 v1.8/v1.9 要求外，还要说明：

- 哪道题承担 Ceiling Diagnostic；
- 哪些题承担 Ceiling Builder；
- Builder 为什么训练特定能力而不是机械重复；
- Final Challenge 与前述题在结构上如何保持足够差异。

题源选择新增一个维度：

> **训练增益价值**：这道题是否能促使学生形成以后可迁移的方法或思维习惯？

因此综合选择标准为：

```text
教学匹配度
+ 权威性
+ 当前可解性
+ 结构新颖度
+ 诊断区分度
+ 训练增益价值
+ 一般化价值
```

# 10. Release Review 新增 R3.6

在 v1.9 的 R3.5 后增加：

## R3.6｜能力上限提升设计

必须检查：

- [ ] 本讲是否有明确 Ceiling Builder；
- [ ] Builder 是否针对 Ceiling Diagnostic 或已知长期习惯中的真实卡点；
- [ ] 是否包含至少一种非机械训练：表示转换 / 条件变化 / 逆向构造 / 多方法 / 一般化 / 陌生迁移；
- [ ] 是否避免提前使用后续知识；
- [ ] Builder 是否与 Diagnostic / Final Challenge 足够区分；
- [ ] 是否设计 T0 → T1 → T2 的能力变化观察；
- [ ] 是否能够说明“本讲希望提高学生哪一种能力”。

R3.6 不通过时，Lesson 可以是优质教学稿，但不能标记为：

> **能力上限提升体系完成。**

---

# 11. 对 Lesson 1～4 的迁移要求

Lesson 1～4 原有 Core、Advanced、Olympiad、Informatics 和 Final Challenge 不因 v2.0 作废。

但需要补两层：

1. v1.9：独立 Ceiling Diagnostic；
2. v2.0：对应的 Ceiling Builder + T0/T1/T2 观察。

在补齐前统一状态：

> **教学内容 PASS；最高深度/能力上限提升体系：REVISE。**

不能因为原课程题目已经很难，就直接判定“能够提升能力上限”。必须指出它具体训练什么，以及延迟迁移是否改善。

---

# 12. Lesson 5 及以后

从 Lesson 5 起首次建设就同时满足：

```text
R0 / R0.5
→ L1～L6
→ R3.5 Ceiling Diagnostic
→ R3.6 Ceiling Builder
→ R4～R11
```

不得再把 Ceiling Diagnostic 或 Ceiling Builder 作为事后补丁。

---

# 13. 最终课程目标

课程最终希望学生逐渐从：

```text
等待老师告诉方法
```

成长到：

```text
自己寻找表示
→ 自己尝试结构
→ 主动检查条件
→ 构造反例
→ 比较方法
→ 从具体抽出一般规律
→ 在陌生问题中独立启动
```

因此最终目标更新为：

$$
\boxed{\text{会认}\rightarrow\text{会用}\rightarrow\text{会解释}\rightarrow\text{会迁移}\rightarrow\text{会独立发现}\rightarrow\text{持续提高独立发现的上限}}
$$
