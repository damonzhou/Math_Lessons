# Math_Lessons 课程标准 v1.6

> **状态**：LOCKED / 已归档  
> **生效日期**：2026-09-01  
> **性质**：v1.5 的增量标准  
> **主题**：Markdown / LaTeX 渲染稳健性与自动检查

---

# 1. 为什么需要 v1.6

课程主要在 GitHub Web / Mobile 阅读。实践中已经出现过两类显示问题：

1. 标题中的简单行内数学，如 `$-5$`，在部分界面直接显示 `$`；
2. 正文中的简单“数值 + 单位”表达，如 `$0^\circ\mathrm C$`，在部分界面也可能原样显示数学标记。

这些表达本身数学上没有错误，但不值得依赖数学渲染器。

因此新增原则：

> **能用普通文本稳定表达的内容，不用 LaTeX；LaTeX 留给真正需要数学排版的结构。**

---

# 2. 标题规则｜强制

Markdown 标题（`#` ～ `######`）中**禁止出现 `$...$`**。

例如：

```markdown
## 错误3：−5 一定表示“减少5”
```

不要写：

```markdown
## 错误3：$-5$ 一定表示“减少5”
```

标题中简单负数、百分数、单位、角度等全部使用普通 Unicode / 文本。

---

# 3. 正文中的简单数值与单位｜优先普通文本

以下类型在普通叙述中原则上不用 LaTeX：

- 单个整数/小数：`−5`、`3.5`；
- 温度：`0 ℃`、`−5 ℃`；
- 长度/质量/时间：`3 cm`、`2 kg`、`5 s`；
- 百分数：`20%`；
- 单纯编号或坐标文字中的简单数字。

例如：

```markdown
温度计以 0 ℃ 作为参考位置。
```

不要写：

```markdown
温度计以 $0^\circ\mathrm C$ 作为参考位置。
```

---

# 4. 什么情况继续使用 LaTeX

下面仍应使用标准 LaTeX：

- 分数、根式、乘方；
- 含变量的表达式；
- 方程、不等式、恒等变形；
- 多项式、函数关系；
- 需要严格数学结构的关系式；
- 多项并列或推导过程。

例如：

```markdown
$\frac12$、$a+b$、$|x|$、$x^2-3x+2=0$
```

块级公式继续使用：

```markdown
$$
...
$$
```

---

# 5. 渲染优先级

课程排版优先级为：

1. **稳定显示**；
2. 数学含义准确；
3. 阅读自然；
4. 排版美观。

不得为了“看起来更数学”而把普通文本强行放进 LaTeX。

---

# 6. 自动 Markdown 渲染检查

仓库维护：

```text
tools/lint_markdown_rendering.py
```

并由 GitHub Actions 自动执行。

至少检查：

- Markdown 标题中是否出现 `$`；
- 是否出现高风险的 LaTeX 温度写法，如 `^\circ\mathrm C`；
- 简单数值是否存在不必要的行内 LaTeX（提示级）；
- 数学内容是否放进不可靠的 HTML 折叠结构。

---

# 7. Release Review 新增 R11

从 v1.6 起，Mainline Lesson 发布 Review 增加：

## R11｜Markdown / LaTeX 渲染稳健性

必须确认：

- [ ] 标题无 `$...$`；
- [ ] 简单数值和单位优先普通文本；
- [ ] 不存在 `$0^\circ\mathrm C$` 一类可直接写成 `0 ℃` 的表达；
- [ ] LaTeX 仅用于真正需要数学结构的内容；
- [ ] 不使用 `<details>` 等原生 HTML 包裹完整数学答案；
- [ ] 自动渲染检查通过。

R11 未通过时，Lesson 不得标记为 PASS。

---

# 8. 与旧课程的关系

- 不要求一次性重写所有历史文件；
- 历史 Lesson 下一次重大修改或重新 Review 时，必须同步迁移到本规则；
- 新 Lesson 从创建开始必须遵守；
- 已经发现的具体渲染问题应立即修复，不等待下一次大版本。

---
